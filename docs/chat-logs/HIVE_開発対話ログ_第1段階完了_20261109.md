## 1. 開発の概要と背景

HIVEは、大学や高等専門学校（高専）の学生が、学校の垣根を越えてプロジェクトを立ち上げ、必要なスキルを持つ仲間を集めて進めるためのWebサービスです。
本ログは、ユーザー（プロダクトオーナー）とフルスタックエンジニア（AI）との全対話、リアルタイム検証、発生した課題とその根本的解決、および実装された全アーキテクチャの記録です。

## 2. 全対話のタイムライン ＆ ユーザー指示・決定事項

### 【フェーズ 1: 現状確認と開発サイクルの確立】
- **ユーザー質問**: 「現状どこまで実装できましたか。エラーや課題、今後実装したいものなどを整理して報告して」
- **対応**: 既存コード（認証、プロフィール、アイデア投稿、AI深掘り、公開アイデア一覧、AI学生マッチング）を調査し、ESLintエラー2件の存在とロードマップを整理・報告。
- **ユーザー指示**: 「作成したデータをリアルタイムで僕が見れるようにして、機能追加後そこで僕が確認、承認したらgithubに保存してほしいんだけどこの設計できる？」
- **決定**: **「リアルタイム確認（ポート3000 Web Preview）＆ 承認駆動（Human-in-the-loop）開発サイクル」** を設計・採用。

### 【フェーズ 2: 画面フリーズ不具合の特定と解消】
- **ユーザー報告**: 「ポート3000で確認できましたありがとう。認証確認中とかアイデアを読込中って表示されて他のボタンも動作しないんだけどこれはまだ開発途中だから？それともバグ？」
- **原因究明**:
  1. Next.jsのSSR（サーバー側HTML生成）の時点で `loading = true` / `ideasLoading = true` が初期値に固定されており、初期HTMLそのものにスピナーが焼き付けられていた。
  2. Cloud ShellのWeb Previewドメイン（`*.cloudshell.dev`）からのアクセスがNext.jsの安全装置でブロックされ、ブラウザにJavaScript（Reactハイドレーション）が届いていなかった。
- **対応**:
  1. 初期状態を `loading = false`, `ideasLoading = false` に改修し、最初からログインボタンや一覧を表示。
  2. `next.config.ts` に `allowedDevOrigins: ["*.cloudshell.dev"]` を追加し、ボタンが正常に動作するよう修正。

### 【フェーズ 3: デモ用プロジェクト10件の投入とログインエラー解消】
- **ユーザー要望**: 「治りましたね。しかし全てのボタンが機能しないので各ボタンの機能実装を進めましょう。それから、仮の公開プロジェクトを10件作成し、表示しておくことで、デモ版紹介時にわかりやすくしましょう」
- **対応**:
  1. 8分野（農業、ものづくり、情報、デザイン、ビジネス、教育、福祉、その他）を網羅したリアルな公開プロジェクト10件と、学生プロフィール7名をFirestoreに一括投入（`scripts/seed.ts`）。
  2. 各プロジェクトに「🤝 足りない役割に合う学生の提案（AIマッチング）」データを最初から付与。
- **ユーザー報告**: 「このドメイン（3000-cs-xxxx.cloudshell.dev）はFirebase Authenticationの『承認済みドメイン』に登録されていません、と表示される」
- **対応**: エラー詳細コードを可視化し、Firebaseコンソールへのドメイン追加手順を案内。ユーザー側で追加完了し、Googleログインが完全開通。

### 【フェーズ 4: 第1段階（土台）の大規模ゼロイチ実装】
- **ユーザー指示**:
  > 「ウェブサービス『HIVE』をゼロから実装するフルスタックエンジニアです。以下の仕様に沿って、学生向けのウェブ画面と、運営だけが入れる管理画面の両方を作ってください。仕様に書かれていない細かい点は妥当な方を選んで進め、何を選んだかを作業報告に一言書いてください。結果を大きく左右する点だけ、作業を止めて質問してください。」
  > 段階1: 土台（登録・ログイン、学校とスキルの一覧A07、利用者の管理A06、操作の記録A09、権限の仕組み）
- **技術選定の合意**:
  - 仕様書推奨のSupabaseに対し、すでに稼働中の **Firebase / Google Cloud（Firestore + Firebase Auth + Storage + Gemini）** をバックエンドとして活用することを提案し合意。
- **実装内容**:
  1. 型定義: `src/lib/types/hive.ts`
  2. デザインシステム: `src/lib/theme.ts`（はちみつ・蜂の巣・色鉛筆手描き質感、4.5:1コントラスト、44pxタップ領域）
  3. 権限ガード: `src/lib/auth-guard.ts`（運営の印のないユーザーの完全遮断、自分の印は外せない不変制約）
  4. 追記専用監査ログ: `src/lib/audit-logger.ts`（変更・削除不可、CSV書き出し）
  5. 運営管理画面: A01審査受付箱、A06利用者管理、A07学校・スキルマスター、A09操作の記録、A02〜A05・A08プレースホルダー（全22ルート完備）
  6. 学生画面共通左メニュー: `StudentSidebar.tsx`（ホーム、スキルツリー、スカウト、申請公開、活動記録、参加中PJ）

### 【フェーズ 5: ユーザーフィードバックに基づく洗練と即時修正】
- **フィードバック 1**: 「左メニュー最下部の 『🛡️ 運営の管理画面へ』（またはURL直接 /admin）がなく、確認できない」
  - **原因**: ログイン中ユーザーへのadminロール同期タイミング。
  - **対応**: サイドバー最下部に「🛡️ 運営の管理画面へ」を常時表示。さらに開発者アカウント（`admin@example.com`）のログイン時は即座に最高運営管理者（`isAdmin: true`）として認識するよう全レイヤーで恒久改修。
- **フィードバック 2**: 「大学名の指定ができない。基本的には自分で入力して、該当大学をプルダウンで選ぶという形にすることで同じ大学で他の呼び名で表記されることを避けたい」
  - **対応**: 入力補完コンボボックス `SchoolCombobox.tsx` を新規開発。「東」「農工」「高専」など柔軟な入力から正式名称（「東京農工大学」等）をプルダウンで確定させ、表記揺れを完全排除。未登録校は「+ 追加依頼」に自動切り替え。
- **フィードバック 3**: 「大学毎に時間割（1限は何時から何時までなど）の情報を共有してユーザーに提案。例外生もいる可能性があるのでその提案は拒否し、ユーザー自身で設定できるようにする。また、大学の中でも最初のユーザーは例がないので提案なしに自分で設定する必要あり。ただし手間のかかる作業なのでスキップできるようにしてあとからでもできるようにして。もしスキップして設定していなくても警告とかはしないで」
  - **対応**:
    1. 大学別時間割テンプレートAPI（`/api/schools/timetable`）を新設。
    2. 代表校の時間割（1限 8:50〜10:20等）の自動提案カードを実装。
    3. 「提案を使わず自分で設定する」から時限時刻の個別手動調整を可能に。
    4. 登録例がない大学では手動調整でき、保存すると次回から他の学生へ提案される共有エンジンを実装。
    5. **上部・下部に「スキップする ✕」「あとで設定する（スキップ）」ボタンを完備。スキップしても警告・催促メッセージを一切出さず、ホームへ進む仕様を完全遵守。**
